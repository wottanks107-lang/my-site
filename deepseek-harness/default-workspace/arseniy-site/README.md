# Arseniy — Personal OS

Личный сайт + приватный dashboard. Next.js 15 (App Router) + TypeScript + GSAP + Three.js.
Без Tailwind — обычный CSS в `app/globals.css`.

## Запуск

```
npm install
npm run dev        # http://localhost:3000
npm run lint       # проверка типов (tsc)
npm run build && npm start   # продакшн-сборка
```

## Переменные окружения

`.env.local` (в git не попадает), образец — `.env.example`:

| Переменная | Зачем | Секрет |
|---|---|---|
| `ADMIN_PASSWORD` | пароль для входа в админку и dashboard | да |
| `AUTH_SECRET` | случайная строка для подписи cookie-сессии | да |
| `NEXT_PUBLIC_SUPABASE_URL` | адрес проекта Supabase | нет |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | публичный ключ для чтения | нет |
| `SUPABASE_SERVICE_ROLE_KEY` | запись в базу, обходит RLS | **да, только сервер** |

Правило: секреты никогда не получают префикс `NEXT_PUBLIC_` и никогда не попадают в git.

## База данных

Схема, правила доступа и bucket для файлов лежат в `supabase/migrations`:

| Файл | Что делает |
|---|---|
| `0001_schema.sql` | таблицы, enum'ы, внешние ключи, индексы, триггеры `updated_at` |
| `0002_rls.sql` | Row Level Security: что видят посетители, что закрыто наглухо |
| `0003_storage.sql` | bucket `site-assets` для картинок и файлов |

Порядок запуска и объяснение архитектуры доступа — в `supabase/README.md`.

Коротко о приватности:

- публичное (профиль, проекты, соцсети, тексты) читается анонимно;
- приватное (расписание, ДЗ, заметки, цели, тренировки, финансы, медиа) закрыто:
  RLS включён, политик нет — анонимный ключ не вернёт ни строки;
- запись запрещена всем, кроме сервера: он использует `service_role` ключ,
  лежащий только в `.env.local`;
- клиентского Supabase-клиента в проекте нет вообще — все чтения в серверных
  компонентах, все записи через route handlers. Поэтому секретный ключ физически
  не может оказаться в браузере.

## Перенос данных

После запуска миграций:

```
npm run migrate -- --dry-run   # посмотреть, что будет перенесено
npm run migrate                # перенести
```

Скрипт читает `data/content.json`, раскладывает старые данные по новым таблицам
и создаёт строку профиля. Запускать повторно безопасно.

## Вход в админку

- Адрес: http://localhost:3000/admin (в подвале сайта есть тихая ссылка «админка»).
- Пароль — `ADMIN_PASSWORD` из `.env.local` (сейчас `arseniy2026`, **поменяй на свой**).
- Сессия живёт 30 дней в подписанной cookie, кнопка «Выйти» — в админке.

## Безопасность

- `.env.local` содержит секретный ключ Supabase и пароль базы. Этот файл **не попадает
  в git** и **не кладётся в архивы**, которые кому-то передаются.
- Секретный ключ (`sb_secret_…`) обходит RLS и даёт полный доступ к базе.
  Он используется только в серверном коде и никогда не попадает в браузер.
- Если секретный ключ или пароль базы где-то засветились — смени их:
  Supabase → Project Settings → API Keys (отозвать ключ) и Database (сбросить пароль),
  после чего обновить `.env.local`.
- Проверка того, что приватные данные закрыты, — `npm run check:db`.
